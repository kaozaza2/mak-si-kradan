# mak-thai

แพลตฟอร์มเกมกระดานออนไลน์ — เล่นบนเบราว์เซอร์ ไม่ต้องสมัครก็เล่นได้

โครงเป็น monorepo ที่แยก backend กับ frontend ออกจากกันชัดเจน

```
apps/
  api/    backend เป็น Python (FastAPI)
  web/    frontend เป็น React + Vite + TypeScript
```

```bash
pnpm install
pnpm api      # backend ที่ http://localhost:8000
pnpm dev      # frontend ที่ http://localhost:5173 (พร็อกซีไปหา backend ให้แล้ว)
```

## backend

```bash
cd apps/api
uv sync --extra dev
uv run uvicorn makthai.main:app --reload   # http://localhost:8000
uv run pytest
uv run ruff check . && uv run ruff format --check .
```

โครงสร้างภายใน:

```
src/makthai/
  domain/     สัญญากลางของแพลตฟอร์ม — ไม่รู้จัก HTTP, ฐานข้อมูล หรือเกมใดเกมหนึ่ง
    types.py       ผลการแข่ง เหตุที่จบเกม การตัดสินผู้ชนะ
    errors.py      ผลของการสั่งเล่น และรหัสข้อผิดพลาดที่ใช้ร่วมกัน
    turnbased.py   ฐานของเกมผลัดตา — ที่นั่ง ลำดับเทิร์น คะแนน การถอนตัว
    bots.py        สัญญาของบอท
    registry.py    ทะเบียนเกม
  games/      กติกาของแต่ละเกม
    mak_si_kradan/   กระดาน กติกา เครื่องสถานะ และบอท
  realtime/   การเล่นออนไลน์ — ไม่รู้จักกติกาเกมเลย
    session.py     ตัวตนที่อยู่ข้ามการหลุดการเชื่อมต่อ
    room.py        ห้องรอเล่น
    match.py       แมตช์ที่กำลังเล่น พร้อมนาฬิกาและการโหวตจบ
    scheduler.py   ตัวตั้งเวลาที่เทสต์เดินเองได้
    hub.py         ศูนย์กลาง
    ws.py          ต่อเข้ากับ WebSocket
  db/         ตารางและการเชื่อมต่อฐานข้อมูล
  services/   บริการที่ประกอบโดเมนกับฐานข้อมูล
    accounts.py    สมัคร ล็อกอิน ค้นหา อันดับ
    friends.py     เพื่อนและคำขอเป็นเพื่อน
    history.py     บันทึกผลการแข่งและคิดอันดับ
  api/        ชั้น HTTP
  auth.py     โทเคนที่โหนดไหนก็ตรวจได้เอง
  rating.py   Elo ที่ขยายไปหลายคน
  messages.py แคตตาล็อกข้อความ
```

ไม่ตั้ง `DATABASE_URL` ก็เล่นได้ครบทุกอย่าง แค่ไม่มีบัญชีผู้ใช้ ไม่มีอันดับ
และไม่เก็บประวัติ การเล่นไม่ควรผูกกับการมีฐานข้อมูล

### เพิ่มเกมใหม่

แพลตฟอร์มไม่รู้จักกติกาของเกมใดเลย มันรู้แค่ว่าเกมหนึ่งต้องทำอะไรได้บ้าง
การเพิ่มเกมจึงไม่ต้องแตะ lobby, การจับคู่, ห้อง, ระบบเพื่อน หรือการกระจายหลาย node

1. สร้างแพ็กเกจใน `src/makthai/games/<ชื่อเกม>/`
2. เขียนคลาสที่สืบทอด `TurnBasedEngine` แล้ว implement สี่เมธอด:
   `apply()` ลงมือเล่นหนึ่งครั้ง · `view()` สถานะที่ client วาด ·
   `auto_play_turn()` เล่นแทนเมื่อไม่มีใครคุมที่นั่ง · `stats()` สรุปผล
   ส่วนลำดับเทิร์น คะแนน การถอนตัว และการจบเกม ฐานจัดการให้แล้ว
3. เรียก `registry.register(GameDefinition(...))` ในไฟล์ `__init__.py` ของเกม
4. เพิ่ม `from makthai.games import <ชื่อเกม>` ใน `games/__init__.py` หนึ่งบรรทัด
5. เพิ่มคำแปลชื่อเกมเป็นรหัส `game_<id>` ใน `messages.py`

`tests/test_registry.py` มีเกมของเล่นที่ทำตามสัญญานี้ทั้งหมดในไม่กี่สิบบรรทัด
ใช้เป็นตัวอย่างได้

### หลักที่ยึดไว้

* **โดเมนไม่รู้จักโลกภายนอก** กติกาเป็น Python ล้วน ทดสอบได้โดยไม่ต้องยกเซิร์ฟเวอร์
* **เซิร์ฟเวอร์ไม่ส่งข้อความภาษาคน** ส่งแค่รหัสกับค่าประกอบ คำแปลอยู่ที่
  `GET /api/v1/messages` ทำให้แอปมือถือเลือกภาษาเองได้ และแก้คำพูดได้โดยไม่ทำให้
  client ที่ปล่อยไปแล้วพัง
* **เซิร์ฟเวอร์เป็นผู้ตัดสิน** client ส่งได้แค่เจตนา ไม่คำนวณกติกาเอง

## frontend

```bash
cd apps/web
pnpm dev        # ต้องเปิด backend ไว้ด้วย
pnpm test
pnpm typecheck
```

หน้าเว็บเป็น **view บาง ๆ บนสถานะที่เซิร์ฟเวอร์ส่งมา** ไม่คำนวณกติกาเองเลย
ใช้ `selectable` / `targets` / `canEndTurn` ที่ได้รับมาเท่านั้น เพราะโหมดกระดานจริง
เซิร์ฟเวอร์จงใจไม่ส่งข้อมูลช่วยเหลือมาให้ ถ้า client เดาเองจะเฉลยคำตอบให้ผู้เล่น

หน้าจอถูกเลือกจากสถานะ ไม่ใช่จาก URL เพราะเซิร์ฟเวอร์เป็นคนบอกว่าตอนนี้อยู่ห้องไหน
หรือเกมไหน กลับมาหลังหลุดแล้วมันส่งของที่ค้างอยู่กลับมาเอง หน้าเว็บแค่วาดตาม

คำแปลแยกเป็นสองชุดโดยตั้งใจ — แคตตาล็อกจากเซิร์ฟเวอร์ใช้แปล *สิ่งที่เซิร์ฟเวอร์บอก*
(ข้อผิดพลาด เหตุการณ์ในเกม) ส่วนป้ายปุ่มและหัวข้อเป็นของหน้าจอล้วน ๆ ที่เซิร์ฟเวอร์
ไม่ควรต้องรู้จัก

## สถานะตอนนี้

เสร็จแล้ว (backend 167 เทสต์ · frontend 9 เทสต์):

* โดเมนกลาง ทะเบียนเกม และฐานของเกมผลัดตา
* หมากสี่กระดานครบกติกา — 2–4 คน, 3 โหมด, บันทึกโอกาสที่พลาด
* บอท 3 ระดับ ที่ลืมกินต่อได้เหมือนคนในโหมดที่ไม่บังคับ
* เล่นออนไลน์ครบวง — จับคู่อัตโนมัติแยกตามเกม, ห้องสาธารณะและส่วนตัว,
  เติมบอทในห้อง, คำเชิญ, นาฬิกาเทิร์น, AI คุมแทนคนที่หายไป,
  กลับเข้าเกมเดิมได้หลังหลุด, โหวตจบเกม, ขอเล่นใหม่
* WebSocket และ HTTP พื้นฐาน
* บัญชีผู้ใช้ อันดับแบบ Elo และประวัติการแข่งพร้อมการเดินทุกเทิร์น
* ระบบเพื่อน — เพิ่มด้วยชื่อผู้ใช้หรืออีเมล เห็นสถานะออนไลน์ และชวนเข้าห้องได้
* หน้าเว็บครบวง — หน้ารวมเกม, หน้าล็อบบี้ของเกม, ฟอร์มสร้างห้อง, ห้องรอเล่น,
  กระดาน, และหน้าสรุปผล

ยังไม่ได้ทำ: ยืนยันอีเมลด้วย OTP, ล็อกอินด้วย Google, การกระจายหลายโหนด
และ Docker สำหรับ deploy
